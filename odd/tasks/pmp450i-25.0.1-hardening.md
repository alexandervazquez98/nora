## Background — verified against production hardware

### Common root cause
Both #57 and #58 stem from the **same systemic issue**: code and tests assumed wire shapes that the real Cambium MIB does NOT emit on PMP 450i firmware 25.0.1. The hermetic test fixtures were built from programmer fantasy, not from `snmpget`/`snmpwalk` captures.

### #57 verified facts
1. `whispLinkEntry` (`1.3.6.1.4.1.161.19.3.1.4.1.*`) is a **per-LUID column table**. The instance `.0` does not exist on a physical AP.
2. `puresnmp.PyWrapper` raises `NoSuchOID` on GET of `.0` (no silent `None`).
3. `Pmp450iDriver._fetch_all` iterates `REQUIRED_OIDS` and currently requests 5 tabu­lar `.0` OIDs that fail on real hardware:
   - `radioDownlinkRate` → `1.3.6.1.4.1.161.19.3.1.4.1.36.0` → `noSuchName`
   - `radioUplinkRate` → `1.3.6.1.4.1.161.19.3.1.4.1.38.0` → `noSuchName`
   - `signalStrengthRx` → `1.3.6.1.4.1.161.19.3.1.4.1.34.0` → `noSuchName`
   - `ssr` → `1.3.6.1.4.1.161.19.3.1.4.1.86.0` → `noSuchName`
   - `modulationMode` → `1.3.6.1.4.1.161.19.3.1.4.1.40.0` → `noSuchName`
4. Sector-level scalars (already in `25.0.1.source.json`) work against live APs:
   - `eirp` → `1.3.6.1.4.1.161.19.3.3.1.306.0` returns `"44 dBm"`
   - `activeTxPowerDbh` → `1.3.6.1.4.1.161.19.3.3.1.233.0` returns `2700`
   - `channelBandwidth` → `1.3.6.1.4.1.161.19.3.3.2.83.0` returns `"20.0"`
   - `carrierFrequency` → `1.3.6.1.4.1.161.19.3.1.10.1.1.1.1` returns `5490000`

### #58 verified facts
1. `linkSessState` (`whispLinkEntry.19`) is an `INTEGER` enum per WHISP-APS-MIB:
   - `idle=0`, `inSession=1`, `clearing=2`, `reRegDnRst=3`, `authChal=4`, `registering=5`, `notInUse=6`.
2. Physical AP on `10.53.7.4` LUID 4 returns `INTEGER: 1` (`inSession`), not the string `"LINKED"`.
3. `subscribers.py` L328 compares `row.link_status == "DOWN"` and L334 compares `row.link_status == "LINKED"` — both never match real wire values, so no subscriber ever lands in `ONLINE_ACTIVE` from production data.
4. `categorize_subscribers` also has a **logical bias**: a subscriber in `pre_existing_offline_subscribers` with `session_uptime > 0` (~24h uptime on the production AP) is condemned to `PRE_EXISTING_OFFLINE` forever, ignoring live signal evidence that the radio recovered.

### WU-E — Categorisation no longer condemns recovered subscribers

**Files**:
- `src/nora/drivers/snmp_pmp450i/subscribers.py` — rewrite the first branch of `categorize_subscribers` (currently L327-330) so that the `pre_existing_list` exclusion is **conditional on zero session uptime**, not absolute:
  ```python
  for row in sm_rows:
      # PRE_EXISTING_OFFLINE: only when the radio is genuinely offline.
      if row.session_uptime == 0:
          buckets["PRE_EXISTING_OFFLINE"].append(row)
          continue
      if row.link_status in _LINK_SESS_OFFLINE_STATES:
          buckets["PRE_EXISTING_OFFLINE"].append(row)
          continue
      # Recovered radio: known_pre_existing_offline_luids does NOT condemn it.
      # (An SM that was down at intervention time and has since re-registered
      # with non-zero session uptime is no longer pre-existing — fall through.)
      if (
          row.session_uptime > 0
          and row.link_status == "inSession"
          and row.modulation not in _DEGRADED_MODULATIONS
          and row.cinr_db >= _CINR_DEGRADED_THRESHOLD_DB
      ):
          buckets["ONLINE_ACTIVE"].append(row)
          continue
      if row.cinr_db < _CINR_DEGRADED_THRESHOLD_DB or row.modulation in _DEGRADED_MODULATIONS:
          buckets["ACTIVE_DEGRADED"].append(row)
          continue
      buckets["ACTIVE_DEGRADED"].append(row)
  ```
- `tests/test_snmp_subscribers.py` — add new named test `test_recovered_subscriber_not_condemned`:
  - SM row with `luid="004"`, `session_uptime=86400` (24h), `cinr_db=22`, `link_status="inSession"`, `modulation="8X"`.
  - `known_pre_existing_offline_luids={"004"}` (was down at intervention time).
  - Assertion: row lands in `ONLINE_ACTIVE`, NOT `PRE_EXISTING_OFFLINE`.

**Fix shape (spec-level)**:
- `pmp450i-radio-tools/spec.md` sub-cluster 2 wording update: a subscriber that has re-registered (non-zero session uptime) is no longer considered "pre-existing offline", even if `intervention_memory` recorded it as such. The exclusion is time-bounded by the radio's own session state.
- Documented in the docstring of `categorize_subscribers` so the next reader sees the intent.

**Evidence gate**: `pytest tests/test_snmp_subscribers.py -v` — all green including the new `test_recovered_subscriber_not_condemned`.
